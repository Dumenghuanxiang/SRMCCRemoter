# SRM 遥控器用户指南

本文对应 SRM Remoter 1.3.0 和“SRM校内赛”v4 协议。App 仅支持横屏，最低要求
Android 12（API 31）。

## 主界面

- 左、右摇杆输出中性的 `LX/LY/RX/RY`；线上统一为 10-bit 有符号量，范围 `-512..511`。
- 十字键、ABXY 和 S1–S6 只表示输入状态；它们对应什么动作由下位机决定。
- 明亮红灯表示未连接，蓝灯表示连接中，绿灯表示已连接，黄灯表示连接或链路异常。状态
  文字同时标明“屏幕输入”或“手柄输入”；点击状态区域可打开设置。
- 顶部“设置”管理连接、手柄中继和运行参数；“调试发送”发送一条 DEBUG 帧。
- 中央调试信息条只预览最近两条记录。点击它可打开完整窗口，按“全部 / 通信 / 数据”
  筛选、暂停跟随最新、清空或复制当前筛选结果。窗口最多保留最近 500 条记录。

所有控制件在未连接时仍可操作。此时 App 不访问蓝牙，而是把编码后的帧写入调试信息，
用于检查摇杆、按键、开关和协议编码，这就是“本地回环”。

## 游戏手柄中继模式

1. 先在 Android 系统蓝牙设置中连接游戏手柄；它必须被系统识别为 Gamepad 或 Joystick。
2. 打开“设置”并开启“手柄中继模式”。App 会选择系统枚举到的第一个手柄；未检测到
   手柄时，开关会自动恢复关闭。
3. App 与从机连接后直接发送 16 字节 PRO_CONTROL，不等待 HELLO；从机按帧 TYPE 自动识别。
4. 关闭“手柄中继模式”开关可恢复屏幕控制。手柄断开或模式退出时，App 会先发送一帧
   全零 PRO_CONTROL；从机仍必须保留 600 ms 失联保护。

PRO_CONTROL 包含双摇杆（`-512..511`）、双扳机（`0..255`）、ABXY、L1/R1、L2/R2、
双摇杆按压、Start、Select、Mode/Home 和四向 D-pad。摇杆使用设备报告的中心死区，D-pad
同时兼容 Hat Axis 和按键事件。v4 不兼容 v3 从机；旧固件必须升级协议核心后才能接收。

## 连接 BLE FFE1

BLE FFE1 是默认传输方式。

1. 打开“设置”，点击“扫描附近 BLE 设备”。
2. 首次使用时允许“附近的设备”权限，并确认系统蓝牙已开启。
3. 等待列表显示名称、MAC 地址、类型和 RSSI，点击目标设备。
4. App 找到可写的 FFE1 特征并完成通知配置后，状态灯变绿，同时振动并显示连接成功提示。

扫描结果出现不代表设备一定实现 FFE1。若提示“FFE1 characteristic not found”或不可写，
请确认模块固件和 GATT 服务，而不是反复配对。

JDY-31 / BLE FFE1 实测链路上限低于 70 Hz，即使模块 UART 调到 115200 bps 也一样。
App 会按用户设置的 1–100 Hz 调度，不会静默降低目标值；链路忙时会覆盖尚未发送的旧
CONTROL，只保留最新状态，从而避免累积延迟。9600 8N1 下，13 字节 CONTROL 的线速
理论上限约为 73.8 Hz，16 字节 PRO_CONTROL 的理论上限为 60 Hz，建议从默认 50 Hz 开始测试。

## 实验性 Bluetooth 3.0 SPP

SPP 默认关闭，适合明确提供 RFCOMM SPP 的经典蓝牙固件。启用步骤如下：

1. 在设置中开启“实验性 Bluetooth 3.0 SPP”并阅读警告。切换模式会断开当前连接，
   同时清除已保存的设备。
2. 点击“扫描经典蓝牙设备”，选择目标设备。
3. 未配对设备会弹出配对码输入框，默认提示值为 `1234`。部分系统还会弹出自己的确认框。
4. 配对完成后，App 依次尝试不安全和安全 RFCOMM，使用标准 SPP UUID 连接。

如果 SPP 出现连接失败、无法断开或无法恢复，应完全关闭 App，然后在 Android 系统设置中
先断开该设备、再执行“取消配对 / 忘记设备”。仅断开连接不够。重新打开 App 后关闭实验性
SPP，恢复默认 BLE FFE1 模式。

## 设置项

| 设置 | 默认值 | 说明 |
|---|---:|---|
| 手柄中继模式 | 关 | 立即检测并转发系统连接的 Gamepad/Joystick；关闭后恢复屏幕输入 |
| 向已连接从机下发控制帧 | 开 | 关闭后停止周期 CONTROL/PRO_CONTROL；DEBUG 仍可发送 |
| 控制帧目标频率 | 50 Hz | 1–100 Hz，步进 1 Hz |
| 实验性 Bluetooth 3.0 SPP | 关 | 关闭时使用 BLE GATT FFE1 |
| 启动时自动重连 | 关 | App 启动时尝试连接上次保存的设备 |
| 意外断联后自动重连 | 关 | 已成功建立的会话异常断开后，以 1/2/4/8/15 秒退避重试 |
| 调试指令自动换行 | 开 | 输入末尾没有 LF 时自动追加 `\n` |
| 保持屏幕常亮 | 开 | App 位于前台时阻止屏幕自动熄灭 |

手柄中继和传输模式切换会立即生效，其余设置在点击右下角悬浮的“确定”按钮后保存。主动
点击“断开当前设备”不会触发意外断联重连。关闭控制帧下发后，下位机例程会在最后一帧
后 600 ms 进入全零安全状态。

## 调试发送与接收

“调试发送”把输入文本按 UTF-8 编码为一条“SRM校内赛”DEBUG 帧，正文最多 64 字节。
开启自动换行时，如果文本没有 LF，App 会追加一个 LF 后再编码。已连接时走当前 BLE/SPP
链路；未连接时只在本地回环中显示十六进制帧。

下位机返回的 ACK、ERROR、LOG、DEBUG 等协议帧会被流式解码并加入调试窗口。固件示例
接受 `PING`、`PING\n` 和 `PING\r\n`，可用它完成第一轮双向测试。完整定义见
[SRM校内赛通信协议](SRM_CAMPUS_COMPETITION_PROTOCOL.md)。

## 权限、数据与隐私

- App 只申请 Android 12+ 的 `BLUETOOTH_SCAN` 和 `BLUETOOTH_CONNECT`，不申请网络或
  位置权限；扫描权限声明为 `neverForLocation`。
- App 本地保存上次设备 MAC 地址和设置项，不包含账号、云服务或遥测。
- 当前 `allowBackup=true`，且未在备份规则中排除偏好设置，因此这些设置及设备地址可能
  参与系统云备份或设备迁移。公开或定制分发时应按产品的数据策略复核该行为。

## 常见问题

| 现象 | 处理 |
|---|---|
| 扫描不到设备 | 确认附近设备权限和系统蓝牙；重新扫描；确认当前 BLE/SPP 模式与模块固件一致 |
| 点击设备后失败 | 打开完整调试窗口，复制“通信”筛选结果；核对 FFE1 特征或 SPP 配对状态 |
| 设置页状态没有刷新 | 等连接流程结束；连接回调会直接更新已打开的设置页，无需返回主界面 |
| 高频时从机低于目标频率 | 先检查串口波特率和分析器统计；JDY-31 FFE1 的实测上限低于 70 Hz |
| 自动重连反复失败 | 主动断开以停止重连，检查供电和模式；SPP 再按上面的完整恢复流程处理 |
| 控件可动但从机无输出 | 检查状态灯、CONTROL 下发开关、下位机 600 ms 失联保护和输入映射 |
| 手柄已连接但没有中继 | 确认 Android 将其识别为 Gamepad/Joystick，并确认从机已实现 v4 PRO_CONTROL |
